### 任务 2：写 common.py

**做什么**：写共享数据结构和工具函数，供所有分析脚本 import

**怎么做**：

创建 `画像分析/common.py`，内容包含：

1. `ChatRecord` dataclass：统一聊天记录结构
   - 字段：time(datetime), content(str), actions(list), outcome(str), learned(list), source(str)
2. `ContentRecord` dataclass：统一内容消费记录结构
   - 字段：time(datetime), title(str), category(str), duration(int), source(str)
3. `write_markdown(path, content)` 函数：写入 Obsidian md 文件
4. `read_trae_sessions()` 函数：读取所有 trae session memory JSONL 文件，返回 `list[ChatRecord]`
   - 路径：`C:\Users\17734\.trae-cn\memory\projects\*\*\session_memory_*.jsonl`
   - 解析 JSONL，每行一个 JSON 对象
   - 字段映射：message_summary_time -> time, intent -> content, actions -> actions, outcome -> outcome, learned -> learned, source 固定为 "trae"
   - 时间解析：`datetime.strptime(s["message_summary_time"], "%Y-%m-%d %H:%M:%S")`

**预期产出**：`画像分析/common.py` 文件，约 60 行

**检查方式**：
```powershell

```
输出应该显示读取到的记录数量和第一条记录的 intent 内容

### 任务 3：写 trae分析.py

**做什么**：写 trae 聊天记录分析脚本，输出方向漂移检测、活跃时段、决策模式三个分析结果

**怎么做**：

创建 `画像分析/trae分析.py`，分 4 个子模块：

#### 3.1 方向漂移检测

**做什么**：分析你在 trae 里实际讨论的主题，跟你声称的方向（Agent/Memory）对比

**怎么做**：
1. 调用 `read_trae_sessions()` 获取所有记录
2. 对所有 `content`（intent）字段做词频统计
3. 定义方向关键词集：
   - Agent 相关：agent, 智能体, mcp, langgraph, multi-agent, tool, function calling
   - Memory 相关：memory, 记忆, vector, embedding, rag, knowledge graph
   - 其他高频词（自动发现）
4. 计算每个方向的提及次数占比
5. 按周分组，看趋势变化（每周的方向提及分布）

**预期产出**：一个 dict，结构如下：
```python
{
    "声称方向": {"主": "Agent", "次": "Memory"},
    "实际TOP10主题": [("小红书", 15), ("定位追踪", 12), ...],
    "方向提及占比": {"Agent相关": 20, "Memory相关": 8, "其他": 72},
    "每周趋势": [("2026-W26", {"Agent": 5, "Memory": 2, "其他": 30}), ...],
    "漂移度判断": "高/中/低 + 说明"
}
```

**检查方式**：运行脚本后，TOP10 主题列表里应该能看到你实际在聊的东西（比如"画像""小红书""定位追踪"），跟声称的 Agent/Memory 方向对比，能得出明确的漂移判断

#### 3.2 活跃时段分析

**做什么**：统计你 24 小时的活跃分布，找出高效时段

**怎么做**：
1. 取所有记录的 `time` 字段
2. 按小时分组统计频次：`Counter(t.hour for t in times)`
3. 识别峰值时段：频次最高的连续 3 小时区间
4. 按工作日/周末分组（可选，数据量够再做）

**预期产出**：
```python
{
    "24小时分布": {0: 2, 1: 0, ..., 23: 5},
    "峰值时段": "22:00-01:00",
    "低谷时段": "03:00-08:00",
    "日均活跃次数": 15.3
}
```

**检查方式**：峰值时段应该符合你的实际感受（大概率是晚上活跃），如果峰值在凌晨说明你是夜猫子

#### 3.3 决策模式分析

**做什么**：分析你遇到问题时"先调研还是先动手"

**怎么做**：
1. 遍历所有记录的 `actions` 列表
2. 对每个 action 做分类：
   - 调研类：包含"搜索""查找""调研""了解""阅读""查看"等词
   - 动手类：包含"写""创建""实现""安装""运行""修改""部署"等词
   - 讨论类：包含"讨论""分析""确认""询问"等词
3. 统计三类占比
4. 计算"想法到动手"间隔：取 intent 中提到的项目，在后续记录中找第一次出现"动手类" action 的时间差

**预期产出**：
```python
{
    "处理路径分布": {"调研类": 35, "动手类": 40, "讨论类": 25},
    "模式判断": "先调研后动手 / 先动手后查 / 混合",
    "想法到动手间隔": "约 N 天（基于X个样本）"
}
```

**检查方式**：三类加起来等于 100%，模式判断符合你的自我认知

#### 3.4 Markdown 输出

**做什么**：把三个分析结果格式化为 Markdown，写入 Obsidian

**怎么做**：
1. 拼接 Markdown 字符串，包含三个 section
2. 调用 `write_markdown()` 写入 `画像产出/trae画像报告.md`
3. 格式参照设计文档中的 v0.1 文档结构

**预期产出**：`画像产出/trae画像报告.md` 文件

**检查方式**：在 Obsidian 中打开该文件，能看到三个分析 section 的结论

**整体验证**：
```powershell
cd d:\AAAmyPrj\gitee\obsidian\我的文档\AI使用\画像分析
python trae分析.py
```
无报错，且 `画像产出/trae画像报告.md` 已生成

### 任务 5：写 marvis分析.py

**做什么**：读取 marvis 的 SQLite 数据库，分析日常诉求和活跃时段

**怎么做**：

创建 `画像分析/marvis分析.py`：

#### 5.1 数据读取

**做什么**：从 marvis data.db 读取聊天记录

**怎么做**：
1. 先复制 data.db 到临时目录（避免 WAL 锁问题）：
   ```python
   import shutil, tempfile, sqlite3
   src = r"C:\Users\17734\AppData\Roaming\Tencent\Marvis\User\2E51332FD5D7CCFEA611C89585433078\database\data.db"
   tmp = tempfile.gettempdir() + "\\marvis_data_copy.db"
   shutil.copy2(src, tmp)
   ```
2. 用 sqlite3 连接复制的文件
3. 查询 messages 表结构：`PRAGMA table_info(messages)`
4. 查询消息记录：`SELECT * FROM messages ORDER BY timestamp`
5. 映射到 `ChatRecord` 结构

**预期产出**：`list[ChatRecord]`，source 为 "marvis"

**检查方式**：
```powershell
python -c "from marvis分析 import *; records = load_marvis(); print(f'读取到 {len(records)} 条 marvis 记录')"
```

#### 5.2 日常诉求分析

**做什么**：分析你在 marvis 里主要问什么

**怎么做**：
1. 取所有记录的 content 字段
2. 做关键词提取/词频统计
3. 按主题分类（技术问题/生活诉求/工具使用/其他）
4. 统计分布

**预期产出**：
```python
{
    "主要诉求TOP10": [("DeepFace部署", 8), ("数据库操作", 6), ...],
    "诉求分类": {"技术问题": 60, "工具使用": 25, "其他": 15}
}
```

**检查方式**：TOP10 应该能反映你实际用 marvis 做的事

#### 5.3 活跃时段分析

**做什么**：同 trae 的活跃时段分析，但数据源是 marvis

**怎么做**：复用 trae分析.py 的活跃时段逻辑，数据源换成 marvis

**预期产出**：同 trae 活跃时段结构

**检查方式**：marvis 和 trae 的活跃时段应该高度重合（都是你的活跃时间）

**整体验证**：
```powershell
python marvis分析.py
```
无报错，`画像产出/marvis画像报告.md` 已生成

### 任务 6：生成个人画像-v0.1.md

**做什么**：合并 trae + marvis 的分析结果，生成综合画像文档

**怎么做**：

1. import trae分析 和 marvis分析 的分析函数

3. 合并活跃时段数据（两源时间戳合并统计）

5. 拼接成完整的 v0.1 文档

### 日常诉求（marvis）

**检查方式**：
1. 在 Obsidian 中打开 `个人画像-v0.1.md`
2. 检查每个 section 是否有数据支撑（不是空话）
3. 检查方向漂移判断是否能反哺信息层 SOP 的方向校准
4. 检查活跃时段是否符合自我认知

**验收标准**：
- [ ] 文档包含 4 个分析维度（方向/决策/活跃/诉求）
- [ ] 每个维度有具体数据（不是定性描述）
- [ ] 方向漂移有明确结论（高/中/低 + 理由）
- [ ] 活跃时段有具体时间段
- [ ] 文档在 Obsidian 中能正常显示
